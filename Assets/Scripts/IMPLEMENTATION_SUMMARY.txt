🎯 QUICK START (5 STEPS):
========================

Step 1: Create FragmentRegistry in Level_1
───────────────────────────────────────────
a) Open Level_1.unity
b) Create empty GameObject: Right-click > Create Empty
c) Name it "FragmentRegistry"
d) Add Component: FragmentRegistry
e) In Inspector, set Fragments size = # of your fragments (e.g., 3)
f) For each fragment:
   - Fragment Name: "blue_fragment" (must match prefab name!)
   - Icon: [drag the sprite]
   - Prefab: [drag the prefab]

Step 2: Duplicate FragmentRegistry to Level_2 and Level_3
────────────────────────────────────────────────────────
a) Drag FragmentRegistry from Level_1 to hierarchy in Level_2
b) Duplicate it again for Level_3
c) Ensure all three have IDENTICAL fragment entries

Step 3: Verify HotbarSystem Configuration
──────────────────────────────────────────
a) Select Player GameObject
b) Find HotbarSystem component
c) Verify these are set:
   ✓ slotImages: [5 Image UI elements]
   ✓ handPoint: [Transform at hand]
   ✓ playerAnimator: [Animator]
   ✓ autoLoadFragments: ENABLED (checked)

Step 4: Ensure Fragment Prefab Names Match
───────────────────────────────────────────
a) In Project, find your fragment prefabs
b) Check each prefab name matches registry (case-sensitive):
   Example: "blue_fragment" prefab → Registry entry "blue_fragment"

Step 5: Test!
─────────────
a) Open Level_1
b) Play
c) Collect a fragment (should appear in hotbar)
d) Open Level_2 directly (don't go through scene transition)
e) Play
f) Fragment should still be in hotbar!

🔧 TROUBLESHOOTING QUICK GUIDE:
===============================

If fragments NOT persisting:
□ Check FragmentRegistry exists in ALL levels
□ Check "autoLoadFragments" is ENABLED in HotbarSystem
□ Check fragment names match EXACTLY (case matters!)
□ Open Console (Ctrl+Shift+C) and look for [Hotbar] messages

If wrong fragment appears:
□ Check FragmentRegistry entries match prefab names
□ Open FragmentPersistenceDebug, call RunDiagnostics()

To test diagnosis:
□ Create empty scene
□ Add player with HotbarSystem and FragmentRegistry
□ Add FragmentPersistenceDebug component
□ In Play mode, call RunDiagnostics() from Console

To reset/clear data:
□ Find HotbarSystem in scene
□ In Console: FindObjectOfType<HotbarSystem>().ClearSavedFragments()

📝 HOW IT WORKS (TECHNICAL):
===========================

Collection Flow:
1. Player collects fragment in Level_1
2. ChestInteraction calls: hotbar.AddItem(icon, prefab)
3. HotbarSystem.AddItem() stores item and calls SaveHotbar()
4. SaveHotbar() saves prefab.name to PlayerPrefs key "Hotbar_Slot_X"
5. Fragment icon appears in UI

Persistence Flow:
1. Scene loads (Level_2)
2. HotbarSystem.Start() calls LoadHotbar()
3. LoadHotbar() reads "Hotbar_Slot_X" from PlayerPrefs
4. For each saved slot, queries FragmentRegistry.GetFragment(fragmentName)
5. Rebuilds hotbar with found prefabs
6. UI displays fragment icons again
7. Player can equip with number keys (1-5)

Data Storage:
- PlayerPrefs keys: "Hotbar_Slot_0", "Hotbar_Slot_1", ..., "Hotbar_Slot_4"
- Values: fragment names (strings)
- Persists: Across play sessions and scene changes
